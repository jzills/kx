A patch for two defects in the output a program reads, both older than 0.9.0 and both found while checking the claims in its release notes against a real cluster.

Output that kx passes straight through from kubectl is now kubectl's own bytes, exactly. It was those bytes plus a trailing blank line: kx ended the document with a newline of its own on top of the one kubectl had already written, so `kx get pods -o json` and `kubectl get pods -o json` differed by a line. Nothing that parses JSON or YAML minds a blank line at the end, which is why it went unnoticed for so long, but it failed any checksum or byte comparison of the two — and being kubectl's own bytes is the whole claim kx makes about these formats.

Asking `kx yaml` for several indexes at once now joins the manifests the way their format joins documents. YAML is unchanged: `---` between them, so `kx yaml 1 2 > pods.yaml` is still a file you can apply. The other formats were being given that same `---`, which belongs to YAML and means nothing anywhere else. In JSON it made the output unparseable — `kx yaml 1 2 -o json | jq` printed the first manifest and then a parse error — and in `-o name` or a Go template's output it was simply a line you had to filter back out. JSON is now merged into the one List kubectl itself answers several names with, and everything else is written as it came.

That last fix changes the shape of one command's output, so a script that worked around the old behavior needs a second look: `kx yaml <several indexes> -o json` is now a List, read as `.items[]` rather than as a stream of objects. One index still prints the bare object, as it always did. Nothing else asks anything of you, and a `~/.kx/state.json` written by 0.9.0 resolves the same indexes.
