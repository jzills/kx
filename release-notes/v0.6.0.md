A name you give a resource now outlasts every listing after it, so the Pod you were watching stays one word away however the numbers move.

- **Marks:** Pinning row 3 with `kx mark api 3` keeps `kx logs @api` working after later listings, on that cluster only.
- **Managing marks:** Listing them is `kx mark`, and `kx unmark api web db` removes them by name.
- **Reading an index:** A new command, `kx ref`, prints what an index means without contacting the cluster.
- **More forwarded flags:** The delete, scale, rollout and yaml commands now forward kubectl's own flags, as `kx get` always has.
- **Empty listings count:** A listing that finds nothing is saved like any other, so an index can no longer reach a resource from the listing before it.

**Breaking:** If a script uses `kx back`, `kx forward` or `kx drop`, change it to `kx state back`, `kx state forward` or `kx state drop`. If it uses an index after an empty listing, it now exits non-zero, and `kx state drop --empty` clears those entries.
