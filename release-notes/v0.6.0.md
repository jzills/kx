Marks are the headline: a mark holds an index under a name, so a resource you pinned stays one word away after later listings renumber everything around it.

- **Marks:** Running `kx mark api 3` pins index 3 as `@api`, and `kx logs @api` keeps working after later listings, on that cluster only.
- **Managing marks:** The `kx mark` command lists what is set, and `kx unmark api web db` removes marks by name.
- **Reading an index:** The new `kx ref` command prints what an index means without contacting the cluster.
- **More forwarded flags:** The `kx delete`, `kx scale`, `kx rollout` and `kx yaml` commands now forward kubectl's own flags, as `kx get` always has.
- **Empty listings retire old indexes:** A listing that finds nothing is saved like any other, so an index can't reach back past it.

If a script uses `kx back`, `kx forward` or `kx drop`, change it to `kx state back`, `kx state forward` or `kx state drop`: the top-level aliases are gone. A script that spends an index after an empty listing now exits non-zero, and `kx state drop --empty` sweeps those entries.
