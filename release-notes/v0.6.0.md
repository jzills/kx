Marks are the headline. `kx mark api 3` pins whatever index 3 resolves to right now under the name `@api`, and `kx logs @api` keeps working after every later listing has moved the numbers around it — which is the one thing an index could never do. A mark records the cluster it was taken in and refuses to resolve anywhere else, `kx mark` lists what is set, and `kx unmark api web db` removes them by name.

Two smaller things worth knowing about. `kx ref 1` prints what an index means without contacting the cluster, for piping into kubectl or reading back before you spend it. And `kx delete`, `kx scale`, `kx rollout` and `kx yaml` now forward kubectl's own flags the way `kx get` always has.

One change asks something of you. A listing that finds nothing is saved like any other now, so the indexes from the listing before it retire instead of staying spendable: `kx get pods -n a` followed by an empty `kx get pods -n b` no longer leaves `kx delete 1` pointing at a pod in `a`, a namespace and two commands away from anything on screen. Spending an index against an empty listing says so and exits non-zero, and `kx state drop --empty` sweeps the entries those listings leave behind.

The top-level `kx back`, `kx forward` and `kx drop` aliases are gone with it. `kx state back`, `kx state forward` and `kx state drop` are the spellings that remain — they have been the canonical ones for long enough that a second spelling of each cost more than it bought — and typing one of the old ones now suggests `kx state` rather than guessing. Scripts using the short forms need updating; nothing else does.
