A release about order: the listings kx draws can now be sorted by their own columns, before they are numbered.

The new `--sort` takes the columns as the header reads them, separated by commas, with a leading `-` for largest-first, and it sorts the table kx prints rather than asking kubectl to reorder the reply — so row 1 is the first sorted row, and the index you spend is the one you read. Each column sorts as what it holds: AGE as a duration, RESTARTS as a count with its `(3m58s ago)` note ignored, READY as a ratio, CPU and MEMORY as quantities, and CPU% and MEM% as percentages. Running `kx get pods --sort -restarts,age` puts the worst-restarting Pod at 1 and settles ties by age; `kx top --sort -mem%` orders by the percentage of each Pod's limit, which kubectl's own `--sort-by` has no column for; and `kx diag --sort -verdict,name` ranks a sweep by severity. It works on `kx get`, `kx top`, `kx secret`, `kx scan` and a `kx diag` sweep, and a key that names no column is refused with the columns actually on screen — `Invalid value for '--sort': 'bogus'. Accepted values: name, ready, status, restarts, age.` Sorting something kx never drew is refused rather than ignored, so a watch, a `-o json`, a `--no-headers` listing and kubectl's `--sum` total row all say so and point you at `--sort-by`.

The `--full` flag on a `kx diag` namespace sweep is now `--show-healthy`, which is what it always did: show the resources that passed beside the ones that failed. The old name is refused rather than quietly accepted. The `--full` on `kx scan` keeps its name — there it means the finding-level report, not a wider listing.

A relist hint is now a command you can paste back. The note kx prints when an index has gone stale names the shape its listing was taken in, quotes a value holding a space, and keeps a value that was deliberately empty, so `kx get pods -n diagnostics --output=wide --sort="nominated node" -m web-healthy` runs and returns the same table rather than failing on a column the default shape never printed. The invocation line at the top of an HTML report is quoted the same way.

Kubernetes kinds are written as types throughout, so a finding reads `CrashLoopBackOff in Pod cache-oom-cc849dbdb-2qdkw` where it used to read `in pod`.

Upgrading asks one thing of you: a script or alias that passes `kx diag --full` has to pass `--show-healthy` instead. Output that is parsed may also have moved — a sweep's findings and kx's own messages now spell kinds as types, and a `kx top nodes` table heads its memory column MEM% whatever your kubectl called it. A `~/.kx/state.json` written by 0.9.2 resolves the same indexes.
