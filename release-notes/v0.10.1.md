A release about getting to the rows you came for: the first few of a sorted listing, or the latest run of each CronJob, numbered so the next command is one index away.

The new `--limit` keeps the first N rows of a listing after `--match` narrows it and `--sort` orders it, and before anything is numbered, so `kx get pods -A --sort age --limit 5` is the five newest Pods as rows 1 to 5 and an index past them names nothing. Piping through `head` cut the table after kx had saved every row, so `kx describe 30` still resolved a Pod you could not see. The caption counts what was kept against what there was — `Pods · all namespaces · 5 of 30 items` — and a refresh lists the same five again. It works on `kx get`, `kx secret` and `kx top`, and output meant for a program (`-o json`, `-o name`, `--no-headers`) refuses it and points you at `head`.

Running `kx get jobs --last-run` lists the newest Job each CronJob has created, one row per CronJob, under a CRONJOB column naming it. The rows are Jobs, so `kx logs 1` reads that run's Pods and `kx describe 1` its conditions and events, where reading LAST SCHEDULE off `kx get cronjobs` and matching names by eye used to be the way. A Job no CronJob created is left out, `-A` keeps two same-named CronJobs in different namespaces apart, and CRONJOB sorts and cuts like any other column: `kx get jobs -A --last-run --sort -age --limit 10`. Asking for `kx get cronjobs --last-run` is refused with the command that does it.

The documentation now travels with the binary. Running `kx docs` lists its pages and `kx docs <topic>` reads one in the terminal, tables drawn as kx draws its own, without a network connection. The same pages answer a new `docs` tool on `kx mcp`, so an agent asked how kx does something reads the documentation for the flags your binary accepts. The site also publishes them as `llms.txt` and `llms-full.txt` for an agent that has text rather than a browser.

Tab completion works for the krew install in zsh. There, `kx` is an alias for `kubectl idx`, and zsh completes an alias as what it stands for, so TAB went to kubectl, which found no way to complete the plugin and listed your directory instead. Run under the name `kubectl_complete-idx`, kx now answers kubectl's completion, and `ln -s ~/.krew/bin/kubectl-idx ~/.krew/bin/kubectl_complete-idx` makes both `kx get pods <TAB>` and `kubectl idx describe <TAB>` offer indexes.

Upgrading asks nothing of you, except one line if you installed through krew and use zsh: add the link above to get completion. If you installed with Homebrew, `brew upgrade jzills/tap/kx` takes this release. A `~/.kx/state.json` written by 0.10.0 resolves the same indexes.
