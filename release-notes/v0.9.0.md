Every command that forwards to kubectl now knows kubectl's flags instead of guessing at them. Until this release kx split argv by hand: it pulled out the flags it recognized, and passed the rest along in the hope that kubectl would make sense of them. That worked until it didn't: `kx logs --tail=2 2` answered `'--tail=2' is not a valid int`, because the index was looked for in a fixed position and a flag had landed there, and per-command `--help` could only list kx's own options because kx had no idea what else kubectl would accept. Each of `get`, `describe`, `logs`, `exec`, `edit`, `delete`, `scale`, `rollout`, `top`, `secret`, `yaml`, `debug`, `cp`, `port-forward`, `label`, `annotate`, `drain`, `cordon`, `uncordon`, `wait` and `set image` now registers kubectl's real flags for its subcommand, from a table generated from kubectl's own source, and lets the parser do the work.

What you get for it shows up at the prompt. Per-command `--help` lists kubectl's flags for that subcommand under "Passthrough options", with their types and kubectl's own descriptions. Completion offers them by name with those same descriptions, and knows what their values look like: filenames for the flags that name a file, directories only for `--kustomize` and `--cache-dir`, and nothing at all for the ones a filename would be meaningless for. An index is found wherever it sits, so the two orderings above are now the same command. Anything after `--` is forwarded without being parsed, and is no longer mistaken for an index.

A mistyped flag is now caught by kx with a message that says which kubectl the table was read from and how to override it: `'--bogus' isn't a flag of kubectl describe as of v1.37.1 … If your kubectl takes it, put it after --`. Because the table and your kubectl can disagree, `kx --version` reports both — the kubectl on your PATH and the release kx's table came from.

The `--match` term now reaches the output formats. `kx get pods -m api -o yaml` returns a List holding only the matching items, re-serialized the way kubectl itself prints YAML, so a narrowed document and an unnarrowed one are the same shape and fold the same way. The same goes for `-o json`, and `--match` composes with `--no-headers` rather than one quietly canceling the other.

The `--no-headers` flag is now read as what it usually means: a program is reading stdout. Everything of kx's own moves out of the way when it is set — the caption above another cluster's rows, the notice that a match found nothing, the offer to replay a stale listing, and the note pointing back to the listing an empty one retired all go to stderr, and the rows stand alone on stdout. Previously each of those printed into the stream being parsed.

Upgrading keeps your history: a `~/.kx/state.json` written by 0.8.0 resolves the same indexes. One change can refuse a command that used to work, and it follows from the first paragraph — a flag that is not in kx's table is now an error rather than something handed to kubectl unexamined. If your kubectl is newer than the table and takes a flag kx hasn't heard of, put it after `--`: `kx describe 1 -- --new-flag`. Nothing else asks anything of you.
