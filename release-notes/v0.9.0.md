Every command that forwards to kubectl now knows kubectl's own flags, from a table generated from kubectl's source, instead of guessing at them. An index is found wherever it sits on the line, so `kx logs --tail=2 2` works.

- **Help for kubectl's flags:** Each command's `--help` lists kubectl's flags for that subcommand under "Passthrough options", with kubectl's own descriptions.
- **Completion for them too:** Completion offers kubectl's flags by name and knows what their values look like, such as filenames for the flags that name a file.
- **Typos caught:** A mistyped flag gets `'--bogus' isn't a flag of kubectl describe as of v1.37.1`, and `kx --version` reports both your kubectl and the one the table came from.
- **Match in output formats:** Running `kx get pods -m api -o yaml` returns a List holding only the matching items, shaped as kubectl prints it.
- **Clean output for scripts:** With `--no-headers` set, everything of kx's own goes to stderr, so the rows stand alone on stdout.

If your kubectl takes a flag kx's table doesn't know, put it after `--`, as in `kx describe 1 -- --new-flag`: an unknown flag is now refused rather than handed to kubectl.
