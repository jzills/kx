Commands that forward to kubectl now know kubectl's own flags, read from a table built from kubectl's source, where kx used to guess at them.

- **Flags in any order:** Flags and an index can come in any order, so `kx logs --tail=2 2` works where it used to fail.
- **Help for kubectl's flags:** Each command's `--help` lists kubectl's flags for it under "Passthrough options", with kubectl's own descriptions.
- **Completion for them too:** Pressing TAB offers kubectl's flags by name and knows their values, such as filenames for a flag that takes a file.
- **Typos caught:** A mistyped flag now gets `'--bogus' isn't a flag of kubectl describe as of v1.37.1`, and `kx --version` names both your kubectl and the table's.
- **Match in output formats:** A narrowed `kx get pods -m api -o yaml` returns a List of only the matching items, shaped as kubectl prints it.
- **Clean output for scripts:** With `--no-headers`, kx's own lines go to stderr, so the rows stand alone on stdout.

**Breaking:** If your kubectl takes a flag kx's table doesn't know, put it after `--`, as in `kx describe 1 -- --new-flag`: an unknown flag is now refused instead of passed on.
