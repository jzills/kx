A patch that makes kx's messages read as one voice, and frees you from a config value kx doesn't recognize.

Errors in kx now share one shape: a sentence that names the problem, then the fix after a dash, with anything you typed in quotes. Refusing keys that are already set, `kx label` used to say `app, pod-template-hash already set; use --overwrite to replace`, and now says `'app' and 'pod-template-hash' are already set — add '--overwrite' to replace them.` The messages for a missing metrics-server, a missing scanner CLI, and `--all` given a name or position read the same way.

An unknown `theme` or `engine` in `~/.kx/config.toml` used to stop every command, including `kx theme` and `kx engine`, the two that set it, so the only fix was editing the file by hand. Those two now run on the default, so `kx theme dracula` repairs the file, and every other command still refuses until you do. If the bad name comes from `KX_THEME` or `KX_ENGINE`, the error names the variable, since saving a choice can't override it.

The help for `kx top` described `--sort-by` and `--show-swap` as pods-only, and the help for `kx rollout` described `--revision` for `status` alone. All three now describe every subcommand that takes them. The binaries are built with Go 1.26.10, for GO-2026-6809.

Upgrading asks nothing of you. Apart from `kx theme` and `kx engine` now running where they used to fail, only the wording of errors and help changed, and a `~/.kx/state.json` written by 0.9.1 resolves the same indexes.
