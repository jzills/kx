Two new commands spend an index where you previously had to copy a name out of a listing. The `kx wait` command blocks until each indexed resource reaches its condition — a Pod or Node Ready, a PersistentVolumeClaim Bound, a Job Complete or Failed, a LoadBalancer Service given an address — and a Job that fails ends the wait with its reason rather than running to the timeout. The `kx set image` command changes an indexed workload's container images and prints each one before and after, so the line it prints says what to type to put it back. Both resolve every index before anything happens, so a typo in the last one costs nothing.

The `--match` term now narrows the sweeps as well as the listings: `kx diag -m`, `kx scan -m` and `kx tree -m` check only the workloads whose name matches. Running `kx state --json` prints what each index currently means — row, kind, name, namespace, and the query and provenance behind the entry — for a script that would rather read kx's state than parse its table. There is also a hosted install script, so `curl -fsSL https://jzills.github.io/kx/install.sh | sh` fetches the newest build for Linux or macOS, checks it against the release's SHA256SUMS, and installs it to `~/.local/bin` without sudo.

Most of the work in this release went somewhere less visible: six review passes over what an index means. A listing of several kinds now numbers each row by its own kind, so `kx get all` is indexable; a stale index is replayed by whichever command listed it, with its namespace, scope flags and match term intact, rather than by a bare `kx get`; a listing read from another cluster prints unnumbered and is not saved; kubectl's warnings on a successful call are no longer swallowed; and an output format gets kubectl's own output on every command that forwards one, with kx's own lines moved to stderr. In the same spirit, `kx yaml` and `kx logs` now keep their banner off stdout and separate manifests with YAML's `---`, so `kx yaml 1 2 > pods.yaml` is a file you can apply; every command answers a missing argument in the same sentence; and a number where a resource type belongs is told so, instead of being passed to kubectl as a kind named `1`.

This release also carries a security fix. Five HTTP/2 advisories — GO-2026-6603, GO-2026-6610, GO-2026-6611, GO-2026-6612 and GO-2026-6617 — were reachable from kx through client-go, in both `golang.org/x/net` and the standard library's own `net/http`, so both had to move: x/net to v0.60.0 and the build toolchain to go1.26.9.

Upgrading keeps your history: a `~/.kx/state.json` written by 0.7.0 still resolves the same indexes. Two things do ask something of you. Building kx from source now needs Go 1.26.9, since that is where the standard library half of those advisories is fixed — the published binaries and wheels already carry it, so this only affects `go install` and local builds. And one change can refuse a command that used to work: see below.
