The headline is `kx mcp`, a Model Context Protocol server that lets an agent — Claude Code, an IDE, an agent framework — read your cluster the way you do: by kind and name, by a mark, or by an index from your current listing. Its ten tools cover listing, diagnosis, ownership, events, logs, usage, manifests and image scans, and every one is read-only against the cluster; `mark`, the one write, only adds a name to kx's own state. Setup is one command: `claude mcp add kx -- kx mcp`.

Start it with `--write-listings` and the agent's listings join your history, tagged as the agent's, so the numbers it hands you are ones you can spend. The `kx state` command says when the current listing came from an agent, and every command that changes something warns before it spends one of that listing's indexes. Without the flag, nothing an agent does touches your listings.

Smaller things: `kx logs` now aggregates a Job's pods, retries included; `kx label` and `kx annotate` forward kubectl's own flags, so `--dry-run` works there too; and a multi-line kubectl error no longer comes out stretched with padding. Every release now also attaches its archives under version-free names, so https://github.com/jzills/kx/releases/latest/download/kx_linux_amd64.tar.gz always fetches the newest build.

Nothing that worked in 0.6.0 behaves differently, so upgrading asks nothing of you.
